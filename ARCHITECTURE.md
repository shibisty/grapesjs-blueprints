# grapesjs-scripts — архитектура

Визуальные скрипты для GrapesJS: блюпринты (графы блоков) компилируются в обычный JavaScript. Работает на ванильном GrapesJS 0.21+, без других плагинов.

```
src/
├─ blueprint/            библиотека, без GrapesJS (тест запрещает импорты оттуда наружу)
│  ├─ core/              модель, реестр, валидация, компилятор, сборка
│  ├─ nodes/             63 встроенных блока (events, flow, dom, data, lib)
│  └─ editor/            визуальный редактор: GraphState (модель правки) + GraphEditor (DOM/SVG) + details
├─ core/                 ScriptsManager (скрипты, библиотеки, настройки — без DOM), libraries, output
├─ integration/          связь с GrapesJS: canvas (превью), components (типы и блоки), export (getHtml), picker
├─ libs/providers.ts     поиск библиотек: jsDelivr/npm, cdnjs, популярные
├─ ui/                   сайдбар, окна (создание, JS, настройки, библиотеки), пипетка, открытие редактора
├─ i18n/                 UI плагина — 23 языка; graph/ — тексты редактора и блоков (ru, uk; en встроен)
└─ plugin.ts             связка: storable, команды, события, API editor.Scripts
proxy/libs-proxy.php     CORS-прокси для поиска библиотек (белый список, кэш)
```

## Ключевые решения

**Компилятор, а не интерпретатор.** Граф превращается в ES5-код, вкладка «JavaScript» показывает ровно то, что уйдёт на сайт. На сайте нет рантайма и `eval`; в код попадают только нужные хелперы `__bp_*`. Каждый блюпринт — `function (root, ctx) → dispose`: превью снимает все обработчики и таймеры.

**Модель исполнения как в UE.** Exec-пины задают порядок, data-пины — типизированные значения. Чистые блоки — выражения в месте использования. Выходы exec-блоков — переменные блюпринта («последнее значение»), объявляются только если выход подключён. Exec-блок с несколькими входящими проводами или в цикле становится функцией. Ошибки отдельных блоков не роняют сборку — уходят в диагностику с `code` и `args` (переводятся по `diag.<code>`).

**События делегируются на document** — работают на всех страницах и для элементов, добавленных позже; `mouseenter/leave` через `mouseover/out` + `relatedTarget`, `focus/blur` → `focusin/out`.

**Хранение — в project data** (storable `scripts`). Storable ставится **первым** (`unshift`): типы компонентных скриптов регистрируются до того, как GrapesJS разбирает страницы, иначе экземпляры загрузились бы как `default`.

**Шаблонные скрипты** — список страниц `editor.Pages` (решается при экспорте: отдельный файл `scripts-<page>.js` только для этих страниц) + рантайм-условие `when` (CSS-селектор).

**Компонентные скрипты** — тип GrapesJS с `script-export` + `script-props` (параметры — трейты с `changeProp`). `script-export` GrapesJS кладёт только в экспорт, в холсте он не выполняется. Изменение скрипта обновляет `script-export` у всех экземпляров.

**Холст.** В режиме правки скрипты не выполняются никогда. В превью (`run:core:preview`) в iframe грузятся JS-библиотеки (по очереди), затем через `<script>` в iframe выполняется preview-сборка и компонентные функции для каждого экземпляра. При выходе — dispose и `wrapper.view.render()`, чтобы всё, что скрипты поменяли в DOM, вернулось к состоянию моделей. CSS библиотек грузится в холст всегда.

**Экспорт.** `editor.getHtml()` обёрнут: добавляет теги библиотек и скриптов (или inline-код). Минификация (terser) и обфускация (javascript-obfuscator) асинхронные и грузятся с CDN только когда включены — результат кэшируется по коду, `getHtml()` берёт готовый, `exportPage/exportSite` всегда ждут.

**Пипетка.** Редактор прячется, клики в iframe перехватываются в фазе захвата (GrapesJS ничего не выделяет), затем окно выбора селектора: `js-`-хуки, data-атрибуты, стабильный id, классы, комбинация классов, атрибуты, id от GrapesJS (помечен как нестабильный), тег — со счётчиком совпадений. Можно добавить элементу класс `js-…` через модель компонента.

**Редактор.** `GraphState` — модель правки без DOM (undo/redo снимками, жест = один шаг, копипаст с новыми id, один провод на data-вход и exec-выход). `GraphEditor` — DOM-ноды + SVG-провода в общем viewport с transform; все keydown останавливаются на корне, чтобы keymaps GrapesJS не сработали на холсте позади.

## Ловушки GrapesJS, найденные по ходу

- `Modal.open({ content: <form> })`: внутренний `$` (cash) считает форму (у неё есть `length`) списком элементов — форма не показывалась. Контент оборачивается в `<div>`. Заменённый контент модалка прячет в «collector» — свой удаляется в `onceClose`.
- `em.changesUp()` срабатывает только при `ready` и через `setTimeout`; без storage счётчик сразу сбрасывается.
- Команда `preview` — старое имя `core:preview`, события `run:/stop:core:preview` приходят для обоих.
- Вьюха, открытая командой (не кнопкой), остаётся активной при переключении кнопок — плагин сам останавливает активные команды кнопок панели.

## Тесты

- `npm test` — vitest + jsdom, реальный grapesjs 0.21.13: компилятор и все блоки (каждый компилируется в валидный ES5), редактор (модель и DOM), менеджер, плагин, экспорт, компоненты, провайдеры (мок HTTP), пипетка, i18n (ключи и плейсхолдеры всех 23 языков).
- `npm run e2e` — headless Chrome + preset-webpage + dist: UI, редактор мышью, превью/пипетка/компоненты/библиотеки/вывод, и сценарий статьи (`e2e/article.mjs`, он же снимает её скриншоты).

## Не сделано / идеи

- Сеть до npm/jsDelivr/cdnjs из браузера не проверена (из облака закрыта) — поиск протестирован на моках; при проблемах с CORS — `proxy/libs-proxy.php`.
- Редактор блоков на 20 языках кроме en/ru/uk (сейчас английский).
- Отладка: подсветка выполняющихся блоков в превью, логи по блокам.
- Подграфы/функции, блок Fetch, пресеты блоков для популярных библиотек (Swiper, GSAP).
- Адаптеры хранения к grapesjs-pages/grapesjs-storage (скрипты уровня сайта при «страница = проект»).
