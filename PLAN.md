## 1. Что делаем

Вкладка **«Скрипты»** рядом со «Страницами»: список скриптов, создание в пару кликов,
а правка — в визуальном редакторе графов (блюпринты), как в UE5 / n8n.

| Вид | К чему привязан | Где работает | Где хранится |
|---|---|---|---|
| **Глобальный** | селектор(ы) | на всех страницах сайта | уровень сайта |
| **Шаблонный** | шаблон / layout | на страницах этого шаблона | уровень сайта, со ссылкой на шаблон |
| **Компонентный** | — | создаёт новый тип компонента (блок), который вставляется на любую страницу; скрипт работает на каждом экземпляре | уровень сайта (определение) + страница (экземпляры) |
| **Библиотека (CDN)** | глобально или на шаблон | подключает JS/CSS по ссылке | уровень сайта |

Блюпринт = граф из блоков (нод), которые перетаскиваются на поле и соединяются проводами.
Запуск — **триггеры**: событие на элементе (click, input, submit, mouseenter…) или
событие страницы (загрузка, скролл, ресайз, таймер, смена hash, своё событие).
Для нестандартного — **нода «JS-код»** со своими входами/выходами.
Любой блюпринт можно посмотреть **как JS** — это ровно тот код, который уйдёт на сайт.

**Первый сквозной тест** — попап: клик по кнопке открывает, клик по «закрыть» закрывает.

## 2. Главные архитектурные решения

### 2.1 Отдельная библиотека, не зависящая от GrapesJS

Делим на три слоя, каждый тестируется отдельно:

```
blueprint/core     модель графа, реестр нод, валидация, компилятор → JS   (без DOM, без GrapesJS)
blueprint/editor   редактор графов (vanilla TS, DOM + SVG)                   (без GrapesJS)
plugin/            вкладка, хранилище, интеграция с GrapesJS, CDN, экспорт
```

На старте `blueprint/` живёт в этом же репозитории (`src/blueprint/`), отдаётся отдельной
точкой входа `grapesjs-scripts/blueprint`, а тест-граница запрещает импорты `grapesjs` и
`../plugin` из неё. Когда API устоится — выносим в свой пакет (`grapesjs-blueprints` или
нейтральное имя) без переписывания.

Это и есть «реализаторы»: нода описывается **данными** (порты, свойства, заголовок,
категория) + **обработчиком** (как превратить ноду в код). Свои ноды добавляются тем же
API, что и встроенные.

```ts
defineNode({
  type: 'dom.addClass',
  category: 'dom',
  inputs:  [{ id: 'exec', type: 'exec' },
            { id: 'target', type: 'elements' },
            { id: 'className', type: 'string', default: '' }],
  outputs: [{ id: 'then', type: 'exec' }],
  helpers: ['list'],                       // маленькие функции рантайма, попадут в код только если нужны
  compile: (c) => `${c.h('list')}(${c.in('target')}).forEach(function (el) { el.classList.add(${c.in('className')}); });
${c.next('then')}`,
});
```

### 2.2 Компилятор, а не интерпретатор

Граф **компилируется в обычный JS**; на сайт уходит только он (плюс нужные хелперы, без
общего рантайма). Причины:
- «Просмотр как JS» — не отдельная фича, а результат компиляции: что видишь, то и работает.
- На сайте нет зависимости от библиотеки, нет загрузки JSON-графа, нет `eval`.
- Код читается и отлаживается обычными DevTools; в нём комментарии с id нод.

Интерпретатор не делаем (иначе каждую ноду пришлось бы писать дважды). Отладка в
превью — через режим компиляции с трассировкой (`__bp.trace('n12')`), который подсвечивает
выполняющиеся ноды в редакторе (как в UE5). Это фаза 8.

### 2.3 Модель исполнения как в UE5

- **Exec-пины** (белые) задают порядок действий: событие → действие → действие.
- **Пины данных** типизированы: `string`, `number`, `boolean`, `element`, `elements`,
  `event`, `object`, `any`. Соединять можно только совместимые; `element → elements`
  приводится автоматически. Цвет провода = тип.
- **Чистые ноды** (без exec: селектор, математика, сравнение, литералы) вычисляются там,
  где их значение нужно.
- От n8n берём не модель исполнения, а удобство: поиск нод, вытягивание провода в
  пустоту → меню нод, подходящих по типу, заметки/группы.

### 2.4 Формат блюпринта (JSON, версионируется)

```json
{
  "schema": 1,
  "id": "bp_popup",
  "name": "Popup",
  "kind": "global",
  "enabled": true,
  "target": { "templateIds": [], "layoutIds": [] },
  "component": null,
  "libraries": [],
  "variables": [{ "id": "v1", "name": "isOpen", "type": "boolean", "default": false }],
  "nodes": [
    { "id": "n1", "type": "event.element", "pos": [80, 120],
      "props": { "event": "click", "selector": ".js-popup-open" } },
    { "id": "n2", "type": "dom.query", "pos": [80, 260], "props": { "selector": "#popup" } },
    { "id": "n3", "type": "dom.addClass", "pos": [380, 120], "props": { "className": "is-open" } }
  ],
  "links": [
    { "from": ["n1", "then"], "to": ["n3", "exec"] },
    { "from": ["n2", "result"], "to": ["n3", "target"] }
  ],
  "comments": []
}
```

Миграции схемы — функции `schema N → N+1`, тестируются на фикстурах.

### 2.5 Во что компилируется попап

```js
/* grapesjs-scripts · "Popup" (global) */
(function () {
  'use strict';
  function list(x) { return x == null ? [] : x.forEach ? Array.from(x) : [x]; }

  // n1: Click on .js-popup-open
  document.addEventListener('click', function (event) {
    var self = event.target.closest('.js-popup-open');
    if (!self) return;
    // n3: Add class
    list(document.querySelectorAll('#popup')).forEach(function (el) { el.classList.add('is-open'); });
  });
  // …закрытие — аналогично, remove class
})();
```

События на элементах по умолчанию **делегируются** на `document` — работает на всех
страницах и для элементов, появившихся позже. Опция «напрямую» — для событий, которые не
всплывают (`mouseenter`, `focus`), там компилятор сам переходит на прямую подписку или
`focusin`/`mouseover`.

Каждый блюпринт компилируется в `function (root) { …; return dispose; }`, чтобы превью в
редакторе могло снять все обработчики при выходе (см. 2.7).

### 2.6 Хранение

После pages 2.0 каждая страница — **отдельный проект** GrapesJS, поэтому глобальные и
шаблонные скрипты **нельзя** класть в project data страницы — они должны жить на уровне
сайта. Делаем так же, как в grapesjs-storage:

- `ScriptStore` (интерфейс) ← `IndexedDbScriptStore` (по умолчанию, БД `gjs-scripts`),
  `MemoryScriptStore`, `RestScriptStore` (контракт `openapi.yaml`: `/scripts`,
  `/libraries`, ревизии, `If-Match` как в pages).
- Опция `storeInProject: true` — для одиночного проекта без pages: всё в своём storable
  `scripts` в project data (как шрифты в grapesjs-fonts).
- Экземпляр компонентного блюпринта лежит в странице как обычный компонент со ссылкой
  `bpId` и значениями параметров; определение типа регистрируется из стора до загрузки
  страницы.

### 2.7 Редактор и холст GrapesJS

- **В режиме правки скрипты на холсте не выполняются** — иначе клик по кнопке открывает
  попап вместо выделения кнопки.
- **Превью** (`core:preview` или своя кнопка ▶): скомпилированный код инжектится во фрейм,
  при выходе — `dispose()` всех блюпринтов и снятие `<script>`/`<link>` библиотек.
- **Пипетка селектора**: кнопка в свойствах ноды → клик по элементу на холсте → стабильный
  селектор. Приоритет: `data-*` атрибут → класс → путь. Автоматические id GrapesJS
  (`#i3kd`) — предупреждение и предложение добавить класс `js-…` прямо в компонент.
- Компонентные блюпринты используют **родной механизм GrapesJS** — `script` +
  `script-props` у типа компонента: параметры блюпринта становятся трейтами, GrapesJS сам
  экспортирует скрипт в `getHtml()`. Нюанс: такие скрипты GrapesJS запускает и в режиме
  правки — проверить и при необходимости обернуть проверкой «мы в превью/на сайте».

### 2.8 Экспорт и публикация

- Команда `scripts:build` → `{ files: { 'scripts/global.js', 'scripts/template-<id>.js' },
  libraries: [{ url, type, integrity, placement }], warnings }`.
- Опция `exportInline`: обёртка `editor.getHtml()` дописывает `<script>`/`<link>` (как
  `exportImport` в шрифтах) — для одиночного проекта.
- С pages в remote-режиме: публикация передаёт серверу скомпилированные файлы, сервер
  подключает global + файлы нужного шаблона на каждую страницу. **Требует доработки
  контракта `openapi.v2.yaml` и Go-рендерера luna-pages** — отдельная задача.
- Рекомендация: отдельные `.js`-файлы, а не inline — так сайт может держать строгий CSP.

### 2.9 CDN-библиотеки (по образцу grapesjs-fonts)

- Провайдеры как `FontProvider`: `LibraryProvider { id, label, search(), versions(), files() }`
  — **jsDelivr** (npm + GitHub, есть хэши файлов для SRI), **cdnjs** (отдаёт SRI),
  **unpkg** (только файлы, без поиска). Порядок = приоритет при дедупликации.
- CORS у API поиска **не проверен** (из облака эти хосты закрыты). Если нет — тот же
  подход, что в шрифтах: PHP-прокси `proxy/libs-proxy.php` с белым списком и кэшем 24 ч.
- Запись библиотеки: `{ name, version (точная, не диапазон), files: [{ url, type: js|css,
  integrity }], placement: head|body, defer|async|module, scope: global|template, enabled }`.
- Ссылки на холст и в экспорт — та же техника, что `syncLinks` в шрифтах (группа
  `data-gjs-scripts`), плюс `<script>` с очередью загрузки (порядок важен: jQuery → плагин).
- Нода «Вызвать функцию библиотеки» (`window.Swiper`, `gsap.to` …) + блюпринт
  объявляет, от каких библиотек зависит → библиотека грузится только там, где нужна.
- Позже: пресеты популярных библиотек со своими нодами (GSAP, Swiper, Alpine) — фаза 9.

## 4. Интерфейс

- **Вкладка «Скрипты»** — кнопка и сайдбар через тот же поиск панели/контейнера, что в
  pages (`findHostPanel`/`findSidebarHost`), с тем же поведением переключения вкладок.
  Группы: Глобальные / Шаблонные / Компоненты / Библиотеки. Создание: имя + вид (+ селектор
  или шаблон). Меню: переименовать, дублировать, вкл/выкл, удалить, показать JS,
  экспорт/импорт JSON.
- **Редактор блюпринта** — полноэкранное окно поверх редактора (в сайдбаре граф не
  помещается):
  - слева палитра (поиск, категории, drag на поле); ПКМ/пробел на поле — поиск нод;
    вытягивание провода в пустоту — меню нод, подходящих по типу;
  - поле: pan/zoom, выделение рамкой, перемещение, удаление, Ctrl+C/V, Ctrl+Z/Y, заметки;
  - справа: свойства ноды, переменные блюпринта, настройки триггера/привязки;
  - вкладки **Граф | JS** (JS только для чтения, с подсветкой; клик по строке → нода);
  - панель ошибок: несоединённые обязательные входы, неверные селекторы, циклы.
- Клавиатура и i18n как в остальных плагинах; RTL.

## 7. Тестирование

- Core: компиляция + исполнение в jsdom для каждой ноды; снапшоты кода; фикстуры
  миграций; фаззинг случайных валидных графов → код парсится (`acorn`) и не падает.
- Плагин: реальный grapesjs 0.21.13 в jsdom, fake-indexeddb, фейковый REST по openapi.
- e2e: headless Chrome + preset-webpage + pages + fonts + context-menu — попап сквозным
  путём, нет JS-ошибок, переключение вкладок Pages ↔ Scripts.

## 8. Безопасность

- JS-нода и любой блюпринт — это код, исполняемый на сайте. В многопользовательской CMS
  сервер должен разрешать сохранять скрипты только доверенным ролям; на клиенте это не
  защищается.
- Без `eval`/`new Function` в рантайме; библиотеки только с точной версией и SRI.

## 9. Решения (2026-11-12)

1. **Редактор графов — свой**, на vanilla TS (DOM + SVG), максимально полный: палитра,
   поиск, вытягивание провода в пустоту, рамка, копипаст, undo/redo, заметки, мини-карта.
2. **Плагин работает на ванильном GrapesJS**, без pages/storage. Отсюда:
   - хранение по умолчанию — свой storable `scripts` в project data (как шрифты);
     `ScriptStore` (IndexedDB/REST) и адаптеры к grapesjs-pages/storage — позже;
   - страницы — нативные `editor.Pages` (в 0.21 есть в ядре);
   - **«шаблонный» блюпринт = условие**: список страниц `editor.Pages` и/или селектор-
     условие на странице (`body.tpl-product`, `[data-template="product"]`), которое
     проверяется в рантайме — так он работает и после экспорта куда угодно.
3. **Вывод — настройки** (у каждого варианта свои плюсы и минусы, в README таблица):
   - `output: 'file' | 'inline'` — отдельный `scripts.js` (кэшируется, строгий CSP) или
     `<script>` в HTML (один файл, проще деплой, но CSP нужен `unsafe-inline`/hash);
   - `minify` — terser, грузится лениво только при включении (≈200 КБ, в бандл не входит);
   - `obfuscate` — javascript-obfuscator, тоже лениво (≈1 МБ+; код медленнее и больше,
     защита условная — по умолчанию выключено).
4. Отдельный npm-пакет библиотеки — позже; пока `src/blueprint/` с тест-границей.
